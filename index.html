atomata-miner.jsATOMATA · n8n
// the heart of ATOMATA: free-text tickets → comparable patterns
// "necesito acceso a X" and "please grant X access" become the SAME pattern
function normalize(summary) {
  return summary.toLowerCase()
    .replace(/[A-Z]{2,}-\d+/gi, '')              // strip ticket ids
    .replace(/\S+@\S+/g, '')                    // strip emails (PII)
    .replace(SYNONYMS, m => CANON[m])            // acceso/access/grant → access
    .split(' ').filter(w => !STOPWORDS.has(w))
    .sort().join(' ');                           // word-order independent key
}
const pattern = patterns.get(normalize(t.summary)) ?? newPattern(t);
pattern.count++; pattern.hours += ESTIMATE[pattern.kind];  // the business case builds itself
Why it matters: native reports count tickets by type; this groups differently-worded but equivalent requests. 20,000+ tickets collapse into 21 actionable patterns — all deterministic, no AI needed in phase 1, PII stripped before anything is stored.

jira-queue.gsinventory hub · Apps Script
// two-way sync, the safe way: changes queue up, then write upstream with receipts
function processQueue() {
  for (const row of pendingChanges()) {
    const asset = findBySerial(row.serial);          // live lookup, never cached ids
    const res = updateAsset(asset.id, row.changes);  // status / user, nothing else
    writeResult(row, res.ok
      ? `\u2705 ${asset.key}: ${describe(row.changes)}`   // human-readable receipt
      : `\u26a0 failed - kept in queue for retry`);
    logHistory(row.who, row.serial, row.changes);    // every change has an author
  }
}
Why it matters: the Inventory Command Center doesn't write blindly — every change is queued, sent, confirmed with a readable receipt, and logged with who did it and when. Auditable two-way sync: the pattern that makes a spreadsheet trustworthy enough to be the single pane of glass.
